Behique CI

Finds out what broke between two versions of a program, and proves it with a test anyone can run again.

The idea

1. Old versionThe one you know works.
+
2. New versionThe one you are about to ship.
=
3. ProofA test that passes on the old version and fails on the new one, every time.

No test, no report. The test proves the behaviour differs between the two versions. Whether that is a bug, and whether to ship, is a person's call.

See it work

We will check FreshRSS, an open-source news reader, comparing old version 1.29.1 with new version 1.30.0. Pick a known case. Behique has to find what changed, prove it, and trace it to the one code change that caused it.

It takes about two minutes and needs nothing from you. Behique is told which buttons to click. In tests, its AI explorer found the Share menu path on its own only after a one-line hint (“some controls only appear after you open an item”), and missed it in two runs without one.

  • Load both versions and record what each page says
    Starts each version from a clean install with the same three articles.
  • Compare old and new
    Anything that changes by itself on every load, like timestamps and security tokens, is learned by loading the old version twice and then ignored.
  • Write a test for the biggest change
    The test states what the old version did.
  • Run that test 3 times on each version
    Each run starts from a fresh install, so luck cannot help.

Where the AI fits

  
The check above has no AI in it, on purpose: a proof has to come out the same every time, so a model is never allowed to declare a bug. The AI does the exploring and the explaining.
