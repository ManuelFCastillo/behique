One line: an autonomous visual QA agent where a bug only counts if a replayable assertion proves it. The demo spine is a two-release regression check: known good release, release candidate, evidence-backed report, a human makes the ship or hold decision.

## Built and verified

### Explorer (src/, earlier phases)
- Explores an unseen web app (screenshot + accessibility tree + network log), reports defects as assertions (data, not model-written code), replays each on a fresh app.
- Self-check rejects ungrounded reports; stability check; Playwright export; BM25 retrieval; token and cost accounting.
- Benchmark: todo-app with 28 planted bugs (27 scored), `node bench.mjs --model baseten|meta`.
- Caveats: results are n=1 and noisy. Tuning test (Meta, 6 bugs): default 4/6, low 3/6, high 1/6, temp 0 0/6, one action 2/6; nothing beat the defaults. `reasoning low` is about 30% cheaper and 40% faster per step but hits the step cap more.

### Release pipeline (src/release/, built 2026-10-28, no model calls)
| File | Job |
|---|---|
| build.mjs, adapters/freshrss.mjs | Check out a git ref (identified by sha), wipe data, install, seed one local feed, serve on a fixed port. About 2 s per build. |
| facts.mjs | Page facts (path to attribute or visible text) after every step. Run-twice masking (`buildBaseline`), `diffFacts`, `rankDiffs` (changed, added, removed, moved). |
| compare.mjs | Base twice + candidate + base a third time as control. |
| diff-builds.mjs | CLI for the above. `node src/release/diff-builds.mjs 1.29.1 1.30.0` |
| confirm.mjs | Top changed fact to a Playwright test (`out/regression/<good>-vs-<cand>/R1.spec.js`), run 3 times per build on freshly seeded builds. `node src/release/confirm.mjs 1.29.1 1.30.0 [--bisect]` |
| scenarios.mjs, adapters/freshrss-scroll.mjs | Named cases the checker can run (`--scenario share\|scroll`): an adapter (feed fixture plus user settings), the clicks to replay, and an honest description stored with each report. The FreshRSS adapter is now a factory, so a scenario is a fixture plus a few settings. |
| evidence.mjs | Evidence store. Append-only event log (`out/evidence/<case>/events.ndjson`, each event carries the hash of the previous one) plus evidence files named by their own sha256. Labelled claims with enforced authorship: only code may write `verified_fact`, `reproduced_failure`, `statistical`; code or a person may write `suspected_cause`; only a model may write `ai_hypothesis` (and must name itself); only a person records `ship` or `hold`. A claim must cite evidence that exists. `verify()` detects edited, removed or reordered events and changed evidence files. Reading a case never creates folders. Tests: `node --test src/release/evidence.test.mjs` (7 pass). |
| hypothesis.mjs | The only paid step. Sends a model (Meta muse-spark-1.3, reasoning low) the observed difference and the one bisected commit's message and diff, capped at 12,000 characters, and nothing else. The diff is wrapped as untrusted data. The answer is recorded as an `ai_hypothesis` claim that cites the exact prompt and reply as evidence. Code then checks the one thing it can: that the line the model says its guess rests on really is in the change (`grounded`). Hard caps: 4,000 output tokens per call, 3 guesses per case, no automatic retry, one call at a time. Projected cost is shown first (`--dry-run`, and on the report page before the button). Tests: `node --test src/release/hypothesis.test.mjs` (offline). |
| bisect.mjs | Binary search over the commits between two refs, using the exported test. Each commit is classified good (test passed), bad (failed on the value assertion itself) or skip (build failed, element missing, timeout: set aside, never guessed). Verified: parent passes 3/3, first bad commit fails 3/3. Removes the checkouts it created. `node src/release/bisect.mjs 1.29.1 1.30.0` |

Also added: `attr` assertion kind in src/assert.mjs and src/export.mjs (not offered to the explorer prompt); exporter takes an optional `start` path.

## Ranked findings (2026-10-31): would a person notice this change?
Until now a version label, a `data-slot` attribute, a React id and a broken share link carried the same weight, and a check whose only proven changes were generated ids was recommended HOLD. `src/release/notice.mjs` (pure rules, no model) gives every changed fact a class: **a person would notice** (text, a link or form target, a state such as disabled or expanded, the page scrolling differently, a link or human text carried in a `data-*` attribute, an image that changed to another image), **markup churn** (generated ids such as `_r_1_`, `:r3:`, `radix-12`; framework `data-*` tokens such as `data-slot` and `data-state`; hashed asset names where only the hash changed; `rel`), or **third-party content** (a `src`, `srcset` or `poster` loaded from a host that is not the app's own). `selectFindings` ranks findings by class before the cap, so the noticeable ones are kept and R1 is the most noticeable (the bisect follows it); third-party content never becomes a finding and is listed as skipped with the host named (the rotating Carbon Ads image on vitepress). The class is written into the `test.exported` and `test.judged` events, the reproduced-failure claim ("This is markup churn (a generated id (for)), not something a person would notice."), the test file's header, the log line ("3 of 3 findings confirmed; 0 a person would notice, 3 markup churn") and the dashboard's build panes. **Recommendation:** when every confirmed finding is churn, `verdictOf` says SHIP and the sub line reads "Only markup churn changed: n proven changes (generated ids, framework attributes), nothing a person would notice"; one noticeable change keeps HOLD; reports made before the classes stay HOLD as before. **What cannot be seen:** the compare phase records a `masking.summary` event (masked facts, total, the page areas with the most masked facts) and the statistical claim ends with where the masked facts sit and "A change inside a masked fact cannot be seen by this check"; the dashboard shows the sentence under the good build. Verified: 690 unit tests (96 on these rules, selection and view-model); umami v3.3.1 vs v3.4.1 rerun in the sandbox: 3 of 3 confirmed as before, all three classed churn (`for` `_r_1_` to `_r_2_`, `data-slot` `button` to `input-group-button` and `loading-button`), recommendation SHIP with the note, 153 s with a warm cache and a reused crawl. Limits: the classes are rules, not learned; a version label in text is "noticeable" by design; a missing element and console or network errors have no class because those facts are not recorded yet.

## A recording for every reproduced failure, one finding per class change, scroll tests that scroll (2026-11-02)

## The regression in plain words, moved content told from new, downloads and copy (2026-11-02)

From the same review, four more. **R means regression test.** The Measured panes say so in a legend ("R1, R2, ... are the regression tests, one per fact that differs between the versions, ranked with the most noticeable first"), and every reproduced-failure record opens with a larger line, "Regression R1 in plain words", before "What the test R1 does": `claimtext.mjs` `regressionText` writes it from the exported test, leading with when and which version ("After a click on 2025.11.2, a split pane that could scroll can no longer scroll: content taller than it is cut off (!overflow-auto to !overflow-hidden)."). ## Class facts and a scroll probe (2026-11-02): what the Hoppscotch miss asked for

Two new facts in `facts.mjs`, both unit-tested and checked in a real browser (recorded, exported, run on a page that scrolls and one that does not): `@class` is the element's class list, sorted and deduplicated (order is not a change), and `#scrolls` is recorded as `y` on any element whose content is taller than its box with overflow auto or scroll. A class change is "a person would notice" only when a class that shows, hides or scrolls comes or goes (`notice.mjs` `LAYOUT_CLASS`: overflow, hidden, invisible, sr-only, opacity-0, pointer-events-none, d-none, the display and position words, with `!` and responsive prefixes); a generated class name (a hash, CSS modules, styled-components, css-/jsx-/svelte- prefixes) is churn, and any other class is churn with a reason that says this check cannot read it. A vanished `#scrolls` fact becomes a test of kind `scrolls` (the same element must still be able to scroll); a class change becomes a `class_list` test that sorts the live classes like the recorded ones; both fail with `toBe`, which the bisect reads as bad (`export.mjs`, `assert.mjs`). In `vanishedRoots`, a lost `#scrolls` is its own entry and never a root that swallows the facts beneath it, since the element is still there. Every reader of fact keys (`findings.mjs`, `notice.mjs` `maskedAreas`, `viewmodel.mjs`, `hypothesis.mjs`, `claimtext.mjs`) knows the new suffix; the dashboard reads a lost area as "a main area can no longer scroll". Not done: an area that newly scrolls is not tested (only the loss is), the page's own scrolling element (`html`) is not probed, and masking will rise on apps that toggle classes on hover or focus (those are noise by the usual rule). Offline suite 841 tests.
